### 0.1 Ten findings a TEAS 2 planner should read first

1. **RLS is real in prod but masked everywhere else.** Dev/CI/test connect as a Postgres superuser (or BYPASSRLS), so the same code that passes 1,400 tests has failed prod startup three times (v1.15.0, v1.22.0, v1.24.0 seed scripts) and silently no-ops in others. The only prod-faithful tests are the few that `SET ROLE pg_database_owner`. **[V]** `troubles-wiki.md` L235, L870, L904.
2. **The only machine interface that is actually public is `/mcp` (+OAuth, +PDF GET).** REST `/api/v1` write routes are fully built (idempotency, fence, rate limit, scopes) but the Next ingress passthrough exports `GET` only and rejects anything not ending in `/pdf` → creating documents over `/api/v1` from the internet is not routed. **[I]** `frontend/app/api/v1/[...path]/route.ts`. (A deferred "Tier-4 live leg" in project memory assumes the opposite.)
3. **Permissions/scopes are defined in ≥6 places** (`Permissions.cs`, `PermissionCatalog.cs`, ~20 SQL grant scripts, role templates, `McpScopes.cs`, FE `ALL_SCOPES`) and held together by parity tests; a seed-ordering bug (320/330 ran before 520) left 6 create/post pairs ungranted until a Cartesian audit found it. **[V]**
4. **Three error shapes, three pagination styles, mixed JSON casing** in one API; the handwritten `openapi.yaml` still claims "API Key + HMAC", "1,000 req/min", "OAuth2 reserved for Phase 2", and a single unified error envelope — code does none of those. **[V]**
5. **Non-super users are effectively single-company** (login takes the first active role assignment; only super-admin can switch company) even though `sys.user_roles` is many-to-many. **[V]** `LoginService.cs`, `AuthEndpoints.cs`.
6. **Jobs are mostly log-only stubs**: the 02:00 "VAT register snapshot" computes and logs, persists nothing; the ภ.พ.30 deadline job only logs a warning; the idempotency purge deletes 0 rows under prod RLS (open, WP-I). **[V]**
7. **e-Tax is scaffolding, not integration**: the XML builder emits skeletal UBL 2.1 while the repo's own spec requires ETDA CrossIndustryInvoice (มกค.14-2563); XSDs are not in the repo; signer is inert without a PFX; the RD client is Mock-only (non-Mock fails startup). **[V]**
8. **Startup does everything**: EF `MigrateAsync` + 111 SQL scripts run inside the API process before `app.Run()`; a failing script/index = restart loop (v2.2.0 needed four manual preconditions). No separate migrate step, no automated backup in repo. **[V]**
9. **The RD form engine is the best-engineered platform piece**: templates embedded, values placed from the template's own AcroForm `/Rect` (plus measured comb-cell JSON), Thai shaped by QuestPDF overlay then flattened. **Keep.** `/paper` canonical model + MCP draft-only/human-approve + claim-first idempotency are the other keepers. **[V]**
10. **Test infra shape is the main velocity tax**: one long-lived shared `teas_test` DB, ~25 min Linux CI for the backend job, "a different test fails each run" flake family, 1,117 `Skip.If(...)` guards that turn a missing DB into a green-looking skip. **[V]**

### 1.2 Who can actually reach what (topology)

```
Browser ──(httpOnly cookie access_token)──► Next.js BFF
            /api/proxy/<backend path>   GET/POST/PUT/DELETE only (no PATCH), 30 s timeout, redirect:'manual'
            /api/auth/{login,logout,refresh,switch-company}  /api/setup/*  /api/onboarding  /api/oauth/accept
MCP agents ──(X-Api-Key XOR OAuth Bearer)──► Next /mcp passthrough ──► backend /mcp (stateless Streamable HTTP)
OAuth clients ──► Next /.well-known/* , /oauth/{authorize,token,register}  (URL rewritten to public origin)
Anyone with a link ──► Next /public/pdf?t=<DataProtection token>  (anonymous)
Integrations ──(X-Api-Key)──► Next /api/v1/*  = GET …/pdf ONLY (scope lock in route handler)
Backend (Kestrel :8080 prod / :5080 dev) has NO public ingress; Cloudflare/Traefik front only the Next app.
```

* Every new externally-reachable backend route needs: a `frontend/app/<path>/route.ts` passthrough **and** a `PUBLIC_PATHS` entry in `frontend/middleware.ts`. Two prod hotfixes came from edge-topology blind spots: `/public/pdf` shipped in v1.13.0 with no passthrough, so MCP-minted links 307'd to `/login` (`troubles-wiki.md` L421); the OAuth consent page sat inside the gated `(dashboard)` layout and was unreachable from a logged-out connect (v1.11.1, L761). `WebApplicationFactory` tests hit the backend directly and cannot see either. **[V]**
* Path collisions: dashboard pages and backend routes share path segments (`/reports/ar-aging` is both an FE page and a backend route); curling the bare path on the public domain hits the FE page (307 to login) — authenticated backend probes must go via `/api/proxy/…`. `troubles-wiki.md` L398. **[V]**
* `/api/v1` write routes: **[I]** not routed publicly (handler exports only `GET` and returns 404 for any path not ending in `pdf`). `frontend/app/api/v1/[...path]/route.ts`.

### 1.5 Gaps / drift (surface these to the TEAS 2 API design)
* **OpenAPI header is wrong on 3 counts [D→V]:** "API Key + HMAC signature, OR OAuth2 client_credentials" (code: X-Api-Key only; OAuth is auth-code+PKCE for `/mcp`), "Rate limit 1,000 req/min per API key" (code: 120/min; the same file's L5304 says 120), and `ErrorEnvelopeV1` described as "unified for ALL paths" (code has the v1 envelope AND RFC 7807 AND `fieldErrors`). The `OAuth2` security scheme says "Reserved for Phase 2" although it is live for `/mcp`.
* **Suffix-matched status mapping** (`.not_found` etc.) means a typo'd code silently becomes 422; no registry/test enumerates codes.
* **`/system/info` is mapped twice** (root + `/api/v1/system/info`) with different permission models; the root `/system/info` and `/system/vat-threshold-status` handlers live inline in `Program.cs` rather than in an endpoint file.
* **Root routes are unversioned and consumed by exactly one client (the FE)** — good for velocity, but it means 300+ contract-less routes (no generated types; FE types in `frontend/lib/types.ts` are hand-maintained).
* **No PATCH, no ETag/If-Match** on the public surface; optimistic concurrency exists in the model (`IConcurrencyVersioned`, `Version`) but is not exposed as a header contract.

### 2.2 Login, session, first-run

* **Login** (`Application/Identity/LoginService.cs`): username+password (BCrypt work factor 12) → optional TOTP (Otp.NET, AES-256-GCM-encrypted secret in `users.mfa_secret_enc`, ±1 step window) → lockout after **5 failures for 15 min** → picks the **first active (company, branch) assignment ordered by company then branch id**; super-admin with no assignment gets `company_id=0` (routes to onboarding). **[V]**
* **Company switching:** only `POST /auth/switch-company/{id}` (super-admin, permission `master.company.manage`, handler re-checks). It re-issues the JWT (RLS follows the token), re-checks the absolute cap, carries the original `auth_time` forward (a 2026-07 fix: repeated switches used to reset the cap), audits `company_switch`. `/me` returns all active companies for a super-admin and **only the own company for everyone else**. A normal user with roles in two companies (the DB allows it: `sys.user_roles(company_id, branch_id, valid_from, valid_to)`) cannot switch. **[V]**
* **Sliding refresh:** `POST /auth/refresh` re-validates active/not-locked from the DB, reloads permissions for the *same* company, copies super flag/company/branch from the caller's token (scope can only shrink), enforces the 10 h cap. FE `useSessionKeepAlive` calls it at ~60 % of remaining TTL, stops after 15 min without input, and a global 401 interceptor opens a re-login modal. **[V]**
* **First run:** `GET /system/setup/status` (anonymous boolean) → `POST /system/setup/bootstrap-admin` (anonymous, succeeds **only when zero users exist**, `pg_advisory_xact_lock` against TOCTOU, password ≥ 12 chars) → `POST /system/setup/instance-keys` (super-admin: writes the MFA AES key + JWT TTL into git-ignored `appsettings.Secrets.json`, `reloadOnChange`, refuses to overwrite an existing MFA key). **[V]**
* **Revocation:** none. `jti` is never consulted; a deactivated user keeps a valid token until expiry (≤ TTL) unless the refresh path runs; role/permission edits take effect on next refresh. Some endpoints (attachments) do a fresh DB permission lookup (`IPermissionLookup`), so **two permission sources coexist** (claims vs DB). **[V]** `troubles-wiki.md` L1036.
* **MFA enrolment does not exist:** `OtpNetTotpService.GenerateSecret/BuildProvisioningUri/Encrypt` have no callers; login honours a stored secret but no API or UI creates one. **[V]**

### 2.3 API keys

`sys.api_keys` (tenant-owned, RLS group G2): name, `key_prefix`, bcrypt `key_hash`, `scopes_json`, `kind`, `default_business_unit_id`, created/last-used/expires/revoked. ### 2.7 Gaps / drift
* **Cookie-size risk [I]:** every permission is a separate `perm` claim in the JWT that lives in a single cookie; a 90-permission role is on the order of 3.5–4 KB base64 against a 4,096-byte cookie limit. Not measured; any growth in permission count (TEAS 2 will want finer granularity) needs a design that keeps permissions server-side or compact.
* **Per-IP limits likely mis-partition behind Docker [I]:** `UseForwardedHeaders(XForwardedFor)` trusts only loopback by default and its comment assumes "Next and the backend always talk over loopback"; `docker-compose.coolify.yml` uses `BACKEND_API_URL=http://api:8080` (container network), so the BFF's forwarded client IP is probably ignored and all users share one login bucket (10/min total). Needs a runtime check.
* **BCrypt on every API/MCP request** (no verified-key cache) — CPU-heavy under bursts of 120/min/key. **[V]**
* **`ValidateOnStart` does not protect the JWT key:** base `appsettings.json` ships a 48-char `REPLACE_WITH…` placeholder that passes the ≥ 32-byte check; no code rejects it, so a prod deploy that forgets `Jwt__SigningKey` would run on a publicly known key. (OAuth certs and the RD provider *are* fail-closed.) **[V]**
* **Secrets file vs containers [I]:** `/system/setup/instance-keys` writes `appsettings.Secrets.json` to the content root; the Coolify compose mounts volumes for attachments/DataProtection/certs but **not** the content root, and the file is added *after* env providers (so it would override env). Persistence across container recreation is unverified.
* **Scope vs permission naming drift:** `sales.quotation.read/create` are MCP scopes that map to RBAC `sales.quotation.manage` (`McpConsentScopes`), `sales.quotation.send` exists only as an `apiperm:` scope, `sys.system_info.read` is a no-permission public read, tax-code/WHT/BU resolver tools borrow `purchase.vendor_invoice.read`, and `McpScopes` still lacks `master.vendor.read` although it exists in `Permissions.cs` — i.e. two namespaces that happen to overlap.
* **MFA enrolment absent** (above); **no password policy beyond ≥ 12 chars on bootstrap and no forced-change flow** (`MustChangePassword` exists on the entity). **[V]**

### 3.3 DB roles and what the tests can see

* Dev DB role and the test connection are **superuser / BYPASSRLS**; CI's `postgres:16` service user is also a superuser (`POSTGRES_USER` becomes superuser). Prod must use a non-superuser NOBYPASSRLS app role — `docker-compose.coolify.yml` carries a comment saying exactly that, because Coolify's one-click Postgres hands out a superuser "and a superuser connection silently bypasses this app's tenant RLS — every company's data becomes visible to every tenant, no error logged". **[V]**
* The fixture tries to provision a NOBYPASSRLS role `teas_rls_test` (needs CREATEROLE); tests fall back to `SET ROLE pg_database_owner` plus an explicit `GRANT SELECT` on the table under test. If neither works, RLS tests **skip** (reported as skipped, not failed). `PostgresFixture.RlsRoleSkip`, `troubles-wiki.md` L695. **[V]**
* Net: RLS correctness is proven only by a handful of purpose-built tests (`Persistence/*RlsTests.cs`, `Identity/*RlsTests.cs`, `ETax/ETaxRetryWorkerRlsTests.cs`, `Scheduling/VatRegisterSnapshotJobRlsTests.cs`); the other ~1,300 tests run RLS-blind.

### 3.4 Ambient tenant context

`Tenancy/AmbientTenantContext.cs` implements `ITenantContext` from the current principal **lazily on every access** (an API-key resolver runs `IApiKeyResolver → AccountingDbContext → ITenantContext` *during* authentication, so a constructor snapshot froze the anonymous user). When `HttpContext` is null (Quartz jobs) it falls back to a settable per-scope company (`SetCompany`), never super-admin, actor `"system"`. Registered as one scoped instance exposed under both the concrete type and the interface. **[V]**

### 3.5 Where tenant scope is *not* enforced (observed coverage, not a verdict)

* **Line/child tables have no `company_id`** (`TaxInvoiceLine`, `JournalLine`, `PaymentVoucherLine`, `ReceiptApplication`, … — checked entity files) → no EF filter and no RLS directly on them; isolation is transitive through the parent FK. A direct `DbSet<…Line>` query is not tenant-filtered at either layer. **[V]** (consequence **[I]**)
* `company_id` present but entity not `ITenantOwned`: `ActivityLog`, `Role`, `RolePermission`, `UserRole`, `CompanyProfile`, `Company` (the tenant root). `ActivityLog`/`Role`/`RolePermission` are covered by RLS group G3 (NULL company = system row); `UserRole` and `CompanyProfile` have neither EF filter nor RLS (explicit `WHERE`s in services). `IdempotencyKey` is RLS-only (the store filters explicitly).
* Global by design: `sys.users`, `sys.permissions`, `sys.document_prefixes` (no `company_id` at all), `master.companies`.
* `ITenantOwned` entities that are *also* reachable by `IgnoreQueryFilters()` exist at login/refresh/OAuth/API-key paths (necessarily).

## 4. TEAS Connect / MCP

### 4.1 Server architecture

* In-process MCP server (`ModelContextProtocol.AspNetCore` 1.4), **stateless Streamable HTTP**: `AddMcpServer().WithHttpTransport(o => o.Stateless = true).AddAuthorizationFilters().AddErrorSurfacingFilter().WithTools<TeasMcpTools>()`, mounted at `/mcp` with the `McpAuth` policy (API key **or** OAuth Bearer; a pre-auth guard returns 400 if both are presented) and the per-key 120/min limiter. Each call resolves scoped services from the request scope that auth already populated → tenant/RLS automatic ("tools never add a manual company filter"). **[V]** `Program.cs` L284–L615.
* `McpErrorSurfacingFilter`: the SDK would otherwise turn every exception into a generic "An error occurred invoking '<tool>'". The filter (registered *after* the auth filter so auth stays outermost) converts `McpE2Exception`, `DomainException`, `FluentValidation.ValidationException`, `JsonException`, `ArgumentException` into `IsError` results prefixed `[mcp.domain_rule]`, `[mcp.validation]`, `[mcp.bad_input]`, `[mcp.arguments]`; everything else keeps the SDK's generic text. **[V]**
* Server instructions are static (cannot vary per company in a stateless server); per-company behaviour is delivered by the `get_workflow_guide` tool (Thai guide for VAT vs non-VAT chains, purchase chain appended). **[V]** `Mcp/TeasServerInstructions.cs`.
* MCP-only input DTOs make `productId`/`customerId`/`vendorId` **non-nullable ("require-list")** so an agent must resolve ids via list/create tools first; unit price is caller-supplied (product master price not applied); `taxRate` is fractional. **[V]**
* Create tools return `DraftCreated { Id, ApprovalUrl, ApprovalLinkMarkdown }` (`{App:BaseUrl}/<route>/{id}?action=approve`); the agent is instructed to paste the markdown link and end the turn.

### 7.2 Bank import

Rules learned the hard way (all in `docs/runtime-gotchas.md` / `troubles-wiki.md`):
1. Each script is **one `ExecuteSqlRawAsync` command inside one transaction** + a ledger row in `sys.applied_sql_scripts` (schema `sys`, **not** `public`; a probe on the wrong schema caused a false rollback). So: **no `{` or `}` anywhere** (EF treats them as `string.Format` placeholders — every recent script header repeats the warning) and **no literal `$2a$12$…` bcrypt hash** (Npgsql parses `$N` as positional parameters → generate with `crypt(…, gen_salt('bf',12))`). A regex quantifier inside a *comment* once broke every test at fixture init.
2. **Ordering footgun:** a grant `INSERT … JOIN sys.permissions` silently inserts zero rows if the permission code is inserted by a later-numbered script (320/330 ran before 520 → fixed by 530). Tests now assert every enforced permission exists in `sys.permissions` (`RbacAuthMapTests` gate 0).
3. **Duplicate numeric prefixes** 240 (×2), 430 (×2), 440 (×3), 450 (×2): order within a tie depends on filename. And prod `DbInitializer` sorts with the default culture-sensitive `OrderBy(p => p)` while `PostgresFixture` sorts `StringComparer.Ordinal` — a latent divergence. **[V]**
4. Seeds must be idempotent (`ON CONFLICT DO NOTHING` + matching unique key) and either company-agnostic or `WHERE EXISTS(company 1)`; anything touching G1/G3 tables needs the pin patterns in §3.6.
5. Relative-date seeds: `400`/`440` use `CURRENT_DATE` to close the previous month, so tests with hard-coded past-month dates fail `period.closed` on a *fresh* DB (a bloated shared DB masked it).
6. Post-squash baseline: prod's ledger only records scripts applied since DB creation, so "repo file count = ledger count" probes are invalid (v1.17.0 false rollback).

Related mechanisms: single atomic `INSERT … ON CONFLICT … DO UPDATE … RETURNING` allocation in `Numbering/NumberSequenceService.cs` on the caller's ambient transaction (a rolled-back post consumes nothing → no gap); `NumberedDocumentWriter` retries up to 50 times with explicit **savepoints** when a drifted bucket collides on a `*_doc_no` unique index; company-wide bucket (`branch_id` bound to 0) since H1. `IAuditable` timestamps are stamped in `SaveChangesAsync`; `IConcurrencyVersioned.Version` tokens guard concurrent edits (e.g. edit-vs-post races).

### 8.5 Gaps / drift
* The data model is described in four places that disagree: EF snapshot (authoritative), `db/schema.sql` ("reference only"), `docs/accounting-system-plan.md` §5 (table list "representative"), and the SQL scripts that alter it.
* **Audit writes are not always atomic with the mutation:** three v1 create paths save the document and the activity row as two `SaveChangesAsync` calls (WP-H, open); `ApiKeyService` and `PrintTrackingService` write `ActivityLog` directly instead of through `ActivityRecorder`.
* No archival/retention job for the 5-year audit requirement; no DB-level partitioning; no documented backup/restore (only a dev dump script and a "take a `pg_dump -Fc` first" line in the cutover checklist).
* Unused schemas `cash`, `notif`, `jobs` are created on every install.

### 9.2 Fixture and database strategy

### 9.4 Known pains (each with its record)

1. **Superuser masks RLS** — see §3.3; only `SET ROLE pg_database_owner`-style tests are prod-faithful; `teas_rls_test` needs CREATEROLE and otherwise **skips** (`troubles-wiki.md` L695).
2. **Apply-once seeds in a long-lived DB** — a new seed cannot assume earlier seeds replay; changing seed structure requires dropping the DB (`backend/tools/ResetTeasTest`); the DB bloats to hundreds of test companies (slow 510 fan-out); random company ids (`Random.Shared.Next(500_000, 699_999)`) collide as it grows (L716, L967); reset recipe L1204.
3. **Relative-date seeds and clocks** — seeds `400`/`440` close "previous month" relative to `CURRENT_DATE`, so hard-coded past-month test dates fail with `period.closed` on a *fresh* DB; document dates are server-pinned to today so tests cannot backdate (L781); tests that compare `DateTime.UtcNow` with Bangkok-pinned validators are green before midnight ICT and red 00:00–07:00 (L911).
4. **Env quirks** — `TEAS_TEST_PG` dies between shell invocations and a missing DB yields *skips that look green* (compare the skip count with the baseline 14); `TEAS_REPO_ROOT` is needed for RBAC tests when run from a `subst` drive (they throw "Could not locate the TEAS repo root" and look like RBAC drift); stale connection strings in old progress notes (L787).
5. **"A different single test fails each run"** (L716): `Pnd50FilingServiceTests`, `WhtFormPdfFillTests`, `TenantIsolationTests` random ids, tax-id collisions in `TestCompanyFactory` — shared mutable rows + unordered classes; rule is isolate-and-rerun.
6. **Harness races** — `Task.Delay(N)` + `IsCompleted==false` pauses are cold-start dependent (idempotency `F1b`, L1749); signal the pause point and assert row counts of setup mutations.
7. **Cross-platform** — the local Windows suite is not a gate for file-system behaviour (an eager `CreateDirectory('/var/teas')` failed 351 Linux CI tests, L1743); `StringBuilder.AppendLine` breaks CSV snapshots across OSes (L766).
8. **PDF assertions** — byte output non-deterministic, PdfPig drops Thai combining marks (L936, L948, L1230).
9. **Coverage blind spots** — HTTP tests bypass the Next ingress (passthrough/`PUBLIC_PATHS` bugs reached prod twice); nothing runs as the prod DB role except the few RLS tests; no load/perf test was ever executed (`docs/test/06-performance-test.md` is a k6 plan only).
10. **Plan vs reality** — `docs/test/01-test-strategy.md` describes Testcontainers-per-class, a staging environment with anonymised snapshots, ~50 e2e specs and a 60/30/10 effort split; reality is one shared DB, no staging, e2e outside CI.
11. **FE e2e** — Sonner toasts never auto-dismiss in headless Chromium (swallow clicks); `getByRole('combobox')`/`cell` ambiguity; soft `if (await btn.count())` guards silently no-op; dashboard scrolls inside `<main>`, not `<body>` (full-page screenshots crop); Windows `vitest.cmd` chokes on paths with parentheses (Next route groups) (L1666, L895, L889, L1486).
